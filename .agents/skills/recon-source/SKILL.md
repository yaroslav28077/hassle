# Фаза 1: разведка сборки ONEAS

0. Проверь, куда указывает `source.build_dir`:
   - **распакованная сборка** (только файлы ONEAS): всё ок, работаем с ней целиком;
   - **установленный Radmir со сборкой внутри**: там тысячи файлов самой игры. Не переносить их! Найди файлы сборки: сравни с чистой копией Radmir (`source.radmir_dir`, если пользователь дал отдельную) по размеру и хэшу, либо по дате изменения (сборка ставилась позже игры). Список файлов сборки сохрани в `work/inventory/build_files.txt` и скопируй их в `work/build_only/` с той же структурой. Дальше работай с `work/build_only/` (`--src work/build_only`). Если отличить не получается, **СТОП** и попроси у пользователя архив сборки.
1. `python tools/inventory.py` → `work/inventory/inventory.csv`, `summary.md`.
2. Если есть `.img`: `python tools/img_extract.py source work/extracted`, затем повтори инвентарь для `work/extracted`:
   `python tools/inventory.py --src work/extracted --out work/inventory/extracted`.
3. Если есть архивы `.zip/.rar/.7z` внутри сборки, распакуй их 7-Zip в `work/extracted/<имя>` и повтори инвентарь.
4. Разберись в структуре сборки:
   - части (обычно папки: «Часть 1», «Интерфейсы», «Графика», «Плагины», «Прицелы», «Звуки» и т.п.);
   - варианты (Basic / Maximum): какие файлы есть только в Maximum;
   - конфиги (`.ini`, `.json`, `.cfg`): прочитай, что они настраивают.
5. Быстрые превью: `python tools/txd_extract.py source work/textures` и посмотри на 10–20 ключевых текстур (HUD, радар, прицелы, иконки), чтобы понимать визуальный стиль.
6. Сформируй `work/inventory/parts.md`: таблица «часть сборки → что внутри → как переносим → приоритет (P1 интерфейс/HUD/прицелы, P2 звуки, P3 модели/текстуры мира, P4 прочее)».

Отчёт пользователю: сколько файлов по категориям, какие части есть, что точно не переносится (код, коллизии, карты) и почему.
