## 1. Как устроено штатное меню настроек и паузы в HASSLE 2.0

1. **`MainMenu.js` + `Settings.js`**:
   - Меню настроек открывается как полноэкранный интерфейс `MainMenu` (`options: { hideChat: !0, hideHud: !0, style: "z-index: 3" }`).
   - Переключение вкладок (`selectTab`, `sendServerEvent`) отправляет клиентские/серверные события (`MainMenu_OnPlayerChangeTab`, `P3_OnPlayerOpenIntefaceMainMenu`, ожидание `UPDATE_SETTINGS` при `isManualOpen`), а сохранение параметров вызывает нативные C++ методы `GameSettings.SaveGraphics()`, `GameSettings.SaveInput()`, `GameSettings.SaveAudio()`, `GameSettings.SaveGeneral()`, `window.saveControlsSettings(...)`.
   - Пока открыт `MainMenu`, HUD полностью скрыт (`hideHud: true`).
2. **`PauseMenu.js` (меню по `ESC`)**:
   - Определено в отдельном чанке `HassleOnline/Content/UserInterface/Main/assets/PauseMenu.js`.
   - Содержит массив `buttons` (`Сменить персонажа`, `Настройки`, `Выйти из игры`) и методы управления (`play()`, `openSettings()`, `openExitModal()`).
   - У `PauseMenu` тоже задан флаг `hideHud: !0` (`options: { hideHud: !0, hideChat: !0, style: "z-index: 3" }`), но курсор уже разблокирован игроком нажатием `ESC`.
3. **`Hud.js` (`HudRadmir`, root `Eg`)**:
   - Корневой компонент HUD всегда смонтирован поверх игры (за исключением экранов с `hideHud: true`).
   - Стили HUD и переключения внешнего вида (классы/атрибуты на корне `.hud-radmir` / `.hud-iface`) применяются мгновенно в реальном времени без перезагрузки.

## 2. Как UI получает ввод и управляет курсором

В `index.js` реализован стек курсора:
- `window.setCursorStatus(id, isActive, forceCapture = false)`: добавляет или удаляет строковый идентификатор `id` из массива активных владельцев курсора `y2`.
- Пока в `y2` есть хотя бы один идентификатор (например `"OneasSettings"`), `window.cursorStatus === true`, и пользователь может нажимать кнопки/переключатели мышью. При удалении идентификатора (`window.setCursorStatus("OneasSettings", false)`) курсор автоматически освобождается (если нет других открытых диалогов/чата).
- В обычной игре курсор заблокирован (управляет камерой), поэтому без открытия чата (`T`) или меню паузы (`ESC`) игрок не сможет кликнуть кнопку на экране, если не используется курсорная точка входа.
- Перехват кликов при закрытой панели не возникает, если контейнер панели рендерится только при `isOpen === true` (либо имеет `pointer-events: none` в закрытом состоянии), а на триггерах входа не вешаются глобальные `keydown`-хоткеи, способные конфликтовать с управлением игры.

## 3. Работает ли `localStorage` в Cohtml HASSLE 2.0

- В коде `index.js` единственный вызов `localStorage` находится внутри `try { localStorage.getItem/setItem } catch {}` обвязки `@vue/devtools-api`. Сама игра настройки в `localStorage` **не хранит** (используются нативные вызовы `GameSettings` / `saveControlsSettings`).
- В `C:\Users\Brain\AppData\Local\HassleOnline\Saved\` папка `LocalStorage` отсутствует до явного использования движком (или Cohtml хранит `localStorage` только в памяти сессии / отдельном профиле, если `UserDataDir` не настроен для `coui://`).
- **Вывод для сохранения настроек ONEAS**:
  1. Чтение и запись строятся по схеме `try { window.localStorage.getItem / setItem } catch {}` с жёсткой валидацией каждого поля (тип + белый список допустимых значений; битые/устаревшие ключи игнорируются с откатом к дефолту).
  2. Начальные значения по умолчанию вшиваются при сборке из `build_options.yaml` (`ONEAS_DEFAULTS`) — их можно менять заранее в `out/configurator.html`.
  3. В самой панели выводится честный статус сохранения (работает ли `localStorage` в текущей сессии и напоминание проверить сохранность после перезапуска игры в рамках пилота `1g`).

## 4. Сравнение вариантов встраивания пункта «Настройки ONEAS»

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **1. Вкладка в `MainMenu` (`Settings.js`)** | Привычное место рядом с настройками графики/звука | Скрывает HUD (`hideHud: true`) — нельзя видеть изменения радара/спидометра вживую; требует патча `MainMenu.js` + `Settings.js`; `MainMenu` шлёт серверные события переключения вкладок | ❌ Не рекомендуется |
| **2. Кнопка «Настройки ONEAS» в меню `ESC` (`PauseMenu.js`) + панель в `Hud.js`** | Работает с разблокированным курсором без новых хоткеев; по клику закрывает `PauseMenu` и сразу открывает панель поверх **живого HUD** (видно изменения в реальном времени); не трогает серверные события `MainMenu` | Требует минимального патча одного якоря в `PauseMenu.js` | ✅ **Основной вход** |
| **3. Маленькая шестерёнка в HUD (`Hud.js`)** | Мгновенный доступ, когда курсор уже открыт (например, через чат `T`) | Когда курсор скрыт (обычная ходьба/езда), нажать мышью нельзя | ✅ **Удобный быстрый вход** (вместе с кнопкой в `ESC`) |

**Итоговая архитектура**:
- **Основной вход**: пункт **«Настройки ONEAS»** в меню паузы `ESC` (`PauseMenu.js`), который закрывает меню паузы (`window.closePauseMenu()`) и вызывает глобальный триггер `window.oneasOpenSettings()` в `Hud.js`.
- **Дополнительный быстрый вход**: аккуратная кнопка-шестерёнка в правом нижнем/верхнем углу HUD (не перехватывает ввод вокруг себя и удобна при открытом чате `T`).
- **Сама панель и состояние (`root data-oneas-*` атрибуты на `.hud-iface`)**: живут целиком внутри `Hud.js` + `Hud.css`, без второго набора JS-логики игры и без сетевых вызовов. При закрытии панель удаляется из DOM (`v-if`) и снимает `"OneasSettings"` со стека `window.setCursorStatus`.
